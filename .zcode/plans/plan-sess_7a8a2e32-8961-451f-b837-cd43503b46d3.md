# 长视频潜空间高清化（二跑）实施方案

## Context

`LKH3LongVideo` 目前的潜空间在采样→解码后被直接丢弃（`gh/long_video.py:670-673`），节点没有任何 LATENT 输出。最终目标：**视频高清化**——第一遍在基础分辨率（默认 0.5MP）分段采样出全片 AV 潜空间 → 潜空间空间放大（如 2×，正好到 H3 训练上限 1920×1088）→ 第二遍低 sigma 精修再生成 → 解码输出高清成片。这正是原 lanxi 版被裁掉的 "latent upscaler + second-pass" 能力（`__init__.py:13-17`）。

## 已验证的关键语义（实现依据）

- **部分重采无需手工加噪**：H3 走 `CONST.noise_scaling`（`comfy/model_sampling.py:94-97`）：`x = σ·noise + (1-σ)·latent_image`。只要把干净 latent 作为 `latent_image` 传给 `guider.sample`、sigma 序列截断到起点 `σ_start=denoise`，ComfyUI 自动完成流插值（`samplers.py:993`）。
- **锁定区每步回填**：`KSamplerX0Inpaint`（`samplers.py:634-643`）在每步模型调用前把 mask=0 区域还原为干净 latent → 二跑音频锁定（mask=0）时输出音频与一跑逐位一致，且会触发既有的 `_clean_locked_latent_inpaint` 补丁（`gh/sampling.py:517`）。
- **H3 latent 无 scale**：`MiniMaxH3Video.scale_factor=1.0`（`latent_formats.py:627`），process_in/out 为恒等，latent 可原样回灌。
- **VAE 解码支持任意 token 数**：H3 VAE 按块解码并自动 pad（`ldm/minimax/vae.py:717-741`），非 5n+2 网格的切片（如 5(n-1) tokens → 17(n-1) 帧）可正确解码。
- **5D 插值**：`comfy.utils.common_upscale`（`utils.py:1140-1172`）原生接受 5D `[B,C,T,h,w]`，支持 nearest-exact/bilinear/area/bicubic/lanczos。
- **对齐数学**：carried 段头部 7 tokens = 22 像素帧（FRAME_PER_TOKEN (1,4,4,4,4)）；裁掉头部后 5n-5 tokens 解码 17(n-1) 帧，与一跑 `frames[22:]` 逐帧对齐；音频头部 36 步 ≈ 0.9s 与波形裁剪一致。

## 工作流（最终形态）

```
LKH3Studio ──segments──▶ LKH3LongVideo ──frames/audio（一跑预览）
                            │  av_latent（新输出：全片嵌套 AV latent + 布局元数据）
                            ▼
                       LKH3AVUpscale（新节点：空间放大 video 部分，音频/mask/元数据保留）
                            │  av_latent
                            ▼
                       LKH3LongVideo.refine_latent（新可选输入 → 二跑模式）
                            │  frames/audio（高清成片） + av_latent（可继续多轮精修）
                            ▼
                       保存/合成
```

## 改动 1：`gh/long_video.py` — runner 输出全片 av_latent

- `_carry_latent` 改为返回 `(out, carry_t, carry_a)`（唯一调用点同步更新），让循环知道每段实际携带量。
- `run_long_video` 循环内收集每段采样后的 video/audio 张量；carried 段裁头部（video 7 tokens、audio 36 步）后沿 T 维拼接。
- mask 统一折叠为单通道（video `[B,1,T,h,w]` / audio `[B,1,2,T_a]`，复用 `_carry_latent` 里已有的 amax 折叠逻辑；缺失的用全 1 补齐）后拼接。
- 新输出（追加在 segment_info 之后，不位移现有 socket）：`av_latent`（`io.Latent.Output`），dict 内容：
  `{"samples": NestedTensor((video_cat, audio_cat)), "noise_mask": ...或None, "gh_h3_audio_mode": mode, "lk_layout": {...}}`
  - `lk_layout` 记录每段 video token 数 / audio 步数、range、latent_continue、h/w —— 二跑切片与校验的唯一事实来源。
- 张量 `.detach()` 移到 intermediate device（与 frames/audio 出口一致）。

## 改动 2：新文件 `gh/latent_upscale.py` — `LKH3AVUpscale` 节点

- 输入：`av_latent`（LATENT）、`upscale_method`（nearest-exact/bilinear/area/bicubic/lanczos，默认 bilinear）、`scale_by`（1.0–4.0，默认 2.0，0.5MP 画布 2× = 1920×1088）。
- 逻辑：`nested_av_parts` 取 video → `common_upscale(video, new_w, new_h, method, "disabled")`；latent h/w 向上取偶（像素 32 对齐 = latent /2 对齐）；video mask 同法插值；audio 部分与 audio mask 原样保留；**其余 dict 键（gh_h3_audio_mode、lk_layout）原样透传**；重建 NestedTensor。
- 输出：`av_latent`（LATENT）。
- V3 schema 写法照抄 `gh/long_video.py:733` 的 `io.ComfyNode` 模式。

## 改动 3：`gh/long_video.py` — runner 二跑模式

- 新输入（追加，optional）：`refine_latent`（io.Latent, optional）、`refine_denoise`（Float，默认 0.45，0.05–1.0）、`refine_audio`（Combo `keep`/`regenerate`，默认 `keep`）。一跑时三者无效（tooltip 说明）。
- `execute` 透传给 `run_long_video(..., refine_latent=..., refine_denoise=..., refine_audio=...)`。
- **refine 分支**（`refine_latent` 已连接时）：
  1. `nested_av_parts` 校验嵌套结构；按 `lk_layout`（缺失则由 plan 推导并强校验总 T 一致，不匹配报清晰错误——如用户改了分段时长）切片出每段 latent。
  2. 每段复用 `build_segment_bundle` 构建 conditioning（keyframe 会在采样时被既有的 `_patch_keyframe_conditioning`（`gh/sampling.py:329`）按放大后的实际网格自动重编码 source_image）；按 range 应用该段 LoRA。
  3. sigma 截断：`native_flow` 精确公式 `base_start = σ_start/(shift − σ_start(shift−1))`，`sigmas = shift_sigma(linspace(base_start, 0, steps+1), shift_video)`（σ_start=1.0 时退化为完整 schedule；其他 scheduler 用"全序列中 ≤σ_start 的部分 + 前插 σ_start"）。
  4. mask 策略：video 全 1（接缝区也要精修，否则锁定区在放大后残留模糊带）；audio：`keep` → 全 0（锁定一跑音频，逐位一致）；`regenerate` → 全 1，并对 audio 部分用修正噪声 `ε' = (σ_a·ε_a + (σ_v−σ_a)·x0_a)/σ_v`（σ_a = `time_shift_sigma(σ_start, shift_v, shift_a)`）补偿双时钟起点差异（已验证 `CONST.noise_scaling` 均匀混合的行为）。
  5. 传 `guider.sample(noise, clean_latent, sampler, sigmas, denoise_mask=...)`；`denoise=1.0` 时等价完整重采。
  6. 跳过 carry 与 CARRY_FRAMES 裁剪（切片已预裁）；解码后直接拼接。
  7. range 为子集时：未选中段的原始切片原样保留，输出 av_latent = 精修段 + 原段拼接（布局不变，可继续多轮精修）；frames/audio 只输出选中段；`segment_info` 记录 pass=refine、denoise、绝对 start_frame（按 layout 累计，便于回拼时间轴）。

## 验证

1. 语法/导入冒烟：用 ComfyUI 自带 python（`F:\ComfyUI-aki-v3.2\python\python.exe`，实现时确认实际路径）对三个文件 `py_compile`；再以 importlib 按包加载 `__init__.py`（ComfyUI 根加入 sys.path）确认注册表含 3 个节点。
2. 纯数学单测（临时脚本放仓库外）：σ 截断公式精确性（`shift_sigma(linspace(base_start,0,N+1))[0] == σ_start`）、切片布局（Σ切片 tokens == 输入总 T，且与一跑帧数逐段对齐）、mask 折叠形状。
3. 端到端由你在 ComfyUI 里跑：一跑 range=1..1（段时长 5s）→ 放大 2× → 二跑 range=1..1 → 核对输出帧数 = 一跑帧数、音频 keep 模式与一跑一致、切换 refine_denoise 观察细节增益；再试 range 子集精修。
